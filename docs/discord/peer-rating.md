# 상호평가 (⭐ 5점)와 국가 추첨식

관리자 명령 하나로 **등록된 모든 플레이어가 자기 자신을 뺀 서로를** 항목별로 ⭐1~5 로 평가한다. 결과는 본인에게 알려 주고, 국가 편성의 균형 자료로 쓴다.

## 1. 라운드

| 단계 | 하는 일 |
|---|---|
| 시작 | 관리자 `/평가 시작 [마감=48h] [항목=기본]` → 대상: `생존자` 역할 전원 |
| 안내 | 각자에게 DM: "평가할 사람 14명" + [평가하기] 버튼. #공지에 진행 임베드 |
| 평가 | 대상 한 명당 모달 하나 (아래 2절). 마감 전까지 수정 가능 |
| 독촉 | 마감 12시간 전, 미완료자에게 DM 한 번 |
| 마감 | 관리자 `/평가 종료` 또는 시간 만료 → 집계 |
| 결과 | 관리자 `/평가 결과` → 본인에게 DM. `공개` 옵션을 줄 때만 #공지에 요약 |

`/평가 현황` 은 누가 몇 명을 평가했는지만 보여 준다. 점수는 보이지 않는다.

## 2. 평가 화면

### 디스코드 모달 (기본)

모달 하나 = 평가 대상 한 명. 모달에는 최상위 컴포넌트를 5개까지 둘 수 있으므로 **항목 5개 = 라디오 그룹 5개**가 딱 맞는다(JDA 6.4 의 모달 라디오 그룹).

```
┌ 영희 (Younghee_) 평가 ──────────────────┐
│ ⚔️ 전투         ○⭐ ○⭐⭐ ○⭐⭐⭐ ○⭐⭐⭐⭐ ○⭐⭐⭐⭐⭐ ○잘 모름 │
│ 🏗️ 건축         …                                  │
│ ⛏️ 생존·자원    …                                  │
│ 🤝 협동·소통    …                                  │
│ 🔥 열정(접속)   …                                  │
│                          [제출]                    │
└────────────────────────────────────────┘
```

- 제출하면 DM 의 진행 표시가 `3 / 14` 로 오르고 다음 대상 버튼이 나온다.
- 라디오 그룹을 쓸 수 없는 상황이면 대체안: 메시지 하나에 문자열 선택 메뉴 5개(행 5개 제한에 맞음).

### 인게임 평가 창 (선택, 상자창)

접속 중인 사람에게 상자창으로 같은 폼을 띄울 수 있다(UI 는 무조건 상자창, 2026-11-23)([README.md](README.md#연동-모드)). 결과는 같은 DB 로 들어간다.

## 3. 항목

| 항목 | 묻는 것 |
|---|---|
| ⚔️ 전투 | PvP·PvE 전투 실력 |
| 🏗️ 건축 | 건축·설계 |
| ⛏️ 생존·자원 | 파밍, 효율, 생존 운영 |
| 🤝 협동·소통 | 팀플레이, 매너, 연락 |
| 🔥 열정(접속) | 얼마나 자주·오래 할 것 같은지 |

- 관리자가 라운드마다 항목을 바꿀 수 있다(최대 5개).
- **'잘 모름'** 을 둔다. 잘 모르는 사람을 억지로 평가하면 자료가 오염된다.
- '최악' 순위나 낮은 점수 공개는 하지 않는다. 친구 사이의 평가라 감정이 상하지 않게 하는 것이 우선이다.

## 4. 집계

대상 t, 항목 c 에 대해 '잘 모름'을 뺀 평가 n 개:

```
1) n ≥ 6 이면 최고·최저 하나씩 버린 평균(절사 평균), 아니면 단순 평균 → m
2) 적은 표본 보정: score = (n·m + 3·μ_c) / (n + 3)      μ_c = 그 항목의 전체 평균
```

- 2) 는 평가가 적게 모인 사람이 극단값을 받지 않게 전체 평균 쪽으로 당긴다.
- 표시: 별은 반올림 정수, 숫자는 소수 한 자리.

```
⚔️ 전투      ⭐⭐⭐⭐☆  3.8
🏗️ 건축      ⭐⭐⭐☆☆  3.1
⛏️ 생존·자원  ⭐⭐⭐⭐☆  4.2
🤝 협동·소통  ⭐⭐⭐⭐⭐  4.6
🔥 열정      ⭐⭐⭐☆☆  2.9
```

### 공개 범위

| 누가 | 무엇을 |
|---|---|
| 본인 | 자기 항목별 점수 |
| 플레이어 전체 | 기본 없음. 관리자가 `공개` 를 고르면 항목별 상위 3명만 |
| 관리자 | 집계와 '이상치 경고'(한 사람이 특정인에게만 극단 점수를 몰아준 경우) |
| 원자료 | 봇 DB 에만. 누가 누구에게 몇 점을 줬는지는 화면에 내보내지 않는다 |

`/info` 에 별점을 띄우는 것은 공개를 고른 경우에만, 설정으로 켠다.

## 5. 국가 추첨식 (팀 편성)

결정과 비교 근거는 zomApo [decisions.md](https://github.com/menonng/zomApo/blob/HEAD/docs/server/decisions.md) 10절, 시뮬레이터는 zomApo `tools/sim/team_sim.py`. 요약: 자유 선택은 국가 격차가 너무 크고(활동량 격차 56~112%), 별점만 쓰는 추첨은 참여도(매일 들어오는 사람 수)를 못 맞춘다. 별점 + 참여도 가중 추첨에 단짝 묶음과 보이지 않는 재추첨 가드를 더하면 활동량 격차 22%, 단짝 91% 유지, 친구와 함께 노는 시간은 자유 선택과 거의 같다(20명/활성 10명).

### 5-1. 입력

| 값 | 출처 |
|---|---|
| 별점 `s_i` | 상호평가 5항목 평균(4절 집계) |
| 참여도 `a_i` | 0.5 × 가입 때 적은 주간 예상 시간 + 0.5 × '열정' 항목 (각각 표준화) |
| 전력 점수 `p_i` | 0.5 × 표준화(s_i) + 0.5 × 표준화(a_i) |
| 핵심 유저 | 예상 시간 상위 (활성 인구 수만큼) |
| 단짝 | 가입 뒤 #등록 의 [단짝 지목] 버튼(디스코드 유저 선택 메뉴)으로 1명. **서로 지목했을 때만** 묶음이 된다. 지목 내용은 본인과 봇만 안다 |
| 팀장 3명 | 원수 지망자 중에서. 지망자가 많으면 전체 투표. 단, 예상 시간 상위 절반에서만 |

### 5-2. 추첨

```
국가 순서를 무작위로 섞는다.
팀장을 각 국가에 넣고, 팀장의 단짝(서로 지목)이 있으면 같은 국가에 넣는다.
남은 사람을 '단위'로 만든다: 서로 지목한 단짝 = 묶음 하나, 나머지 = 한 명씩.
국가를 순서대로 돌며, 그 국가에 자리가 남았으면:
    후보 = 자리에 들어가는 단위들
    가중치(u) = 0.08 + max(0, |m − μ| − |m'(u) − μ|) / σ × (현재 인원)
        m = 지금 국가 평균 전력, m'(u) = u 를 넣은 뒤 평균, μ = 전체 평균, σ = 전체 표준편차
    가중치에 비례해 한 단위를 뽑아 넣는다
```

- 국가 평균이 전체보다 높으면 낮은 사람이, 낮으면 높은 사람이 뽑히기 쉽고, **격차가 클수록 확률이 커진다.** 0.08 바닥 덕분에 누구든 어느 국가로나 갈 수 있다(결과가 뻔하지 않다).
- 국가 인원은 `⌈N/3⌉` / `⌊N/3⌋` 로 맞춘다. 묶음이 들어갈 자리가 없으면 마지막에 묶음을 풀어 한 명씩 넣는다.

### 5-3. 재추첨 가드 (보이지 않음)

뽑은 결과가 아래를 모두 만족할 때까지 처음부터 다시 뽑는다(최대 500번, 넘으면 가장 가까운 결과).

| 기준 | 값 |
|---|---|
| 핵심 유저 수 차이 | 1 이하 |
| 국가 총 예상 시간의 (최대 − 최소) / 평균 | 18% 미만 |
| 국가 평균 별점 차이 | 0.35 이하 |
| 국가 인원 차이 | 1 이하 |

시뮬레이션상 평균 30~45번, 500번 안에 99% 이상 통과한다. 계산은 1초가 안 걸리고, 사람들은 통과한 결과만 본다. 기준을 만족하는 결과들 가운데 하나가 가중 추첨 확률대로 고르게 나오므로 '정해진 정답'이 아니다.

### 5-4. 추첨식과 공정성

1. `/팀 팀장 <3명>` → 팀장 확정, #공지에 알림.
2. `/팀 추첨` → 봇이 시드를 만들고 **시드의 SHA-256 해시를 먼저 #공지에 올린다.**
3. 봇이 5-2·5-3 을 돌려 통과한 결과를 만든다.
4. #공지에서 10초 간격으로 한 명씩 공개: `🎲 2국 ← 영희 (단짝 철수와 함께)`. 국가별 막대(전력·예상 시간)가 점점 채워진다.
5. 공개가 끝나면 **시드를 공개**한다. 누구나 같은 입력·시드로 같은 결과를 재현할 수 있다(봇 저장소의 추첨 코드 + 공개 입력: 별점 대신 순위 구간만 공개해 개인 점수는 드러내지 않는다).
6. `/팀 교환` → 24시간 맞교환 창. 서로 다른 국가 두 사람이 서로 신청하면 봇이 5-3 기준을 계속 만족하는지 보고 허락한다.
7. `/팀 확정` → 국가 역할 부여, 국가 카테고리·채널 생성, 모드로 `nation.assign`, 팀장 = 원수, 국가 이름 투표.

국가와 출발지(정삼각형 꼭짓점)의 짝은 이것과 별개로 개장 방송에서 추첨한다.

### 5-5. 예비: 최적화 편성

추첨이 맞지 않는 상황(인원이 크게 늘거나 줄어 가드 통과가 어려울 때)을 위해 관리자 전용 `/팀 최적화` 를 남겨 둔다. 목적함수는 아래와 같고, 20명 이상은 분할 수가 수천만~수십억이라 전수 탐색 대신 담금질(무작위 맞바꿈 + 점점 엄격하게)을 여러 번 돌려 서로 다른 상위 3안을 낸다.

```
J =  10 · Var_국가( Σ a_i / 평균 )            활동량 합 균형
   +  4 · Var_국가( 평균 s_i )                 별점 균형
   + 10 · (핵심 유저 0명인 국가 수) + 2 · [핵심 유저 차 ≥ 2]
   + 100 · (깨진 단짝 수) + 100 · [인원 차 > 1]
```

## 6. 그 밖의 쓰임

- **시즌 후 평가(선택)**: 시즌이 3주라 중간 평가 대신 시즌이 끝난 뒤 같은 항목으로 한 번 더. 시즌 전과 비교한 '성장'을 본인에게 보여 주고, 다음 시즌 편성 자료로 쓴다.
- **시즌 결산**: 시즌 MVP 투표(항목 없이 한 명 고르기)를 같은 틀로 진행.
- **이적 판단 자료**: 시즌 중 이적 창을 열 때 활동량 균형 확인.
