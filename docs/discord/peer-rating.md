# 상호평가 (⭐ 5점)와 균형 팀 편성

관리자 명령 하나로 **등록된 모든 플레이어가 자기 자신을 뺀 서로를** 항목별로 ⭐1~5 로 평가한다. 결과는 본인에게 알려 주고, 국가 편성의 균형 자료로 쓴다.

## 1. 라운드

| 단계 | 하는 일 |
|---|---|
| 시작 | 관리자 `/평가 시작 [마감=48h] [항목=기본]` → 대상: `생존자` 역할 전원 |
| 안내 | 각자에게 DM: "평가할 사람 14명" + [평가하기] 버튼. #공지에 진행 임베드 |
| 평가 | 대상 한 명당 모달 하나 (아래 2절). 마감 전까지 수정 가능 |
| 독촉 | 마감 12시간 전, 미완료자에게 DM 한 번 |
| 마감 | 관리자 `/평가 종료` 또는 시간 만료 → 집계 |
| 결과 | 관리자 `/평가 결과` → 본인에게 DM. `공개` 옵션을 줄 때만 #공지에 요약 |

`/평가 현황` 은 누가 몇 명을 평가했는지만 보여 준다. 점수는 보이지 않는다.

## 2. 평가 화면

### 디스코드 모달 (기본)

모달 하나 = 평가 대상 한 명. 모달에는 최상위 컴포넌트를 5개까지 둘 수 있으므로 **항목 5개 = 라디오 그룹 5개**가 딱 맞는다(JDA 6.4 의 모달 라디오 그룹).

```
┌ 영희 (Younghee_) 평가 ──────────────────┐
│ ⚔️ 전투         ○⭐ ○⭐⭐ ○⭐⭐⭐ ○⭐⭐⭐⭐ ○⭐⭐⭐⭐⭐ ○잘 모름 │
│ 🏗️ 건축         …                                  │
│ ⛏️ 생존·자원    …                                  │
│ 🤝 협동·소통    …                                  │
│ 🔥 열정(접속)   …                                  │
│                          [제출]                    │
└────────────────────────────────────────┘
```

- 제출하면 DM 의 진행 표시가 `3 / 14` 로 오르고 다음 대상 버튼이 나온다.
- 라디오 그룹을 쓸 수 없는 상황이면 대체안: 메시지 하나에 문자열 선택 메뉴 5개(행 5개 제한에 맞음).

### 인게임 다이얼로그 (선택)

접속 중인 사람에게 바닐라 다이얼로그로 같은 폼을 띄울 수 있다([mod.md](mod.md)). 결과는 같은 DB 로 들어간다.

## 3. 항목

| 항목 | 묻는 것 |
|---|---|
| ⚔️ 전투 | PvP·PvE 전투 실력 |
| 🏗️ 건축 | 건축·설계 |
| ⛏️ 생존·자원 | 파밍, 효율, 생존 운영 |
| 🤝 협동·소통 | 팀플레이, 매너, 연락 |
| 🔥 열정(접속) | 얼마나 자주·오래 할 것 같은지 |

- 관리자가 라운드마다 항목을 바꿀 수 있다(최대 5개).
- **'잘 모름'** 을 둔다. 잘 모르는 사람을 억지로 평가하면 자료가 오염된다.
- '최악' 순위나 낮은 점수 공개는 하지 않는다. 친구 사이의 평가라 감정이 상하지 않게 하는 것이 우선이다.

## 4. 집계

대상 t, 항목 c 에 대해 '잘 모름'을 뺀 평가 n 개:

```
1) n ≥ 6 이면 최고·최저 하나씩 버린 평균(절사 평균), 아니면 단순 평균 → m
2) 적은 표본 보정: score = (n·m + 3·μ_c) / (n + 3)      μ_c = 그 항목의 전체 평균
```

- 2) 는 평가가 적게 모인 사람이 극단값을 받지 않게 전체 평균 쪽으로 당긴다.
- 표시: 별은 반올림 정수, 숫자는 소수 한 자리.

```
⚔️ 전투      ⭐⭐⭐⭐☆  3.8
🏗️ 건축      ⭐⭐⭐☆☆  3.1
⛏️ 생존·자원  ⭐⭐⭐⭐☆  4.2
🤝 협동·소통  ⭐⭐⭐⭐⭐  4.6
🔥 열정      ⭐⭐⭐☆☆  2.9
```

### 공개 범위

| 누가 | 무엇을 |
|---|---|
| 본인 | 자기 항목별 점수 |
| 플레이어 전체 | 기본 없음. 관리자가 `공개` 를 고르면 항목별 상위 3명만 |
| 관리자 | 집계와 '이상치 경고'(한 사람이 특정인에게만 극단 점수를 몰아준 경우) |
| 원자료 | 봇 DB 에만. 누가 누구에게 몇 점을 줬는지는 화면에 내보내지 않는다 |

`/info` 에 별점을 띄우는 것은 공개를 고른 경우에만, 설정으로 켠다.

## 5. 균형 팀 편성

시뮬레이션상 완전 랜덤 편성이면 핵심 유저가 한 명도 없는 국가가 생길 확률이 15명/활성 4명에서 45.1%, 10명/활성 3명에서 70.0% 다(zomApo [simulation.md](https://github.com/menonng/zomApo/blob/HEAD/docs/server/simulation.md)). 그래서 평가를 편성에 쓴다.

### 5-1. 입력

- 항목 점수 벡터 `s_i = (전투, 건축, 생존, 협동, 열정)`
- 예상 활동량 `a_i = 0.5 × 정규화(열정) + 0.5 × 정규화(가입 때 적은 주간 예상 시간)`
- 접속 시간대 집합 `T_i` (가입 때 체크박스)
- 합의 조건: 같이 하고 싶은 쌍(반드시 같은 국가), 피하고 싶은 쌍(관리자만 보는 비공개 입력)

### 5-2. 목적 함수 (작을수록 좋음)

```
J =  w1 · Var_국가( Σ a_i )                    활동량 합 균형
   + w2 · Σ_c Var_국가( 평균 s_i,c )             항목별 평균 균형 (전투만 몰리지 않게)
   + w3 · (핵심 유저 0명인 국가 수)               a_i 상위 = 핵심 유저
   + w4 · (깨진 합의 조건 수)
   − w5 · Σ_국가 평균 Jaccard(T_i, T_j)          같은 국가끼리 접속 시간대가 겹칠수록 좋음
```

기본 가중치: w1 = 1, w2 = 0.5, w3 = 10, w4 = 100, w5 = 0.5.

**w5(시간대 겹침)** 는 시뮬레이션에서 나온 "자국민 없이 노는 시간이 59~74%" 를 줄이기 위한 항이다. 실력이 같아도 같은 시간에 들어오는 사람끼리 묶여야 함께 논다.

### 5-3. 탐색

인원이 적으므로 **모든 분할을 다 따져 본다.**

| 인원 | 국가 크기 | 분할 수 |
|---|---|---|
| 10 | 4 / 3 / 3 | 2,100 |
| 12 | 4 / 4 / 4 | 5,775 |
| 15 | 5 / 5 / 5 | 126,126 |

15명이어도 1초 안팎이다. J 가 작은 순으로 **서로 충분히 다른 상위 3개 안**(국가 구성원이 2명 이상 다른 것)을 고른다.

### 5-4. 확정

1. `/팀 편성` → 세 안을 임베드로 보여 준다(국가별 명단, 활동량 합, 항목 평균 막대, 시간대 겹침).
2. 플레이어가 버튼으로 투표. 친구끼리 바꾸고 싶은 요청은 #공지 스레드에서 합의.
3. `/팀 확정 <안>` → 국가 역할 부여, 국가 카테고리·채널 생성, 모드로 `nation.assign`.
4. 각 국가 채널에서 원수 투표, 국가 이름 투표.

국가와 출발지(정삼각형 꼭짓점)의 짝은 이것과 별개로 개장 방송에서 추첨한다.

## 6. 그 밖의 쓰임

- **중간 평가(6주차, 선택)**: 같은 항목으로 한 번 더. 시즌 초와 비교한 '성장'을 본인에게 보여 준다.
- **시즌 결산**: 시즌 MVP 투표(항목 없이 한 명 고르기)를 같은 틀로 진행.
- **이적 판단 자료**: 시즌 중 이적 창을 열 때 활동량 균형 확인.
